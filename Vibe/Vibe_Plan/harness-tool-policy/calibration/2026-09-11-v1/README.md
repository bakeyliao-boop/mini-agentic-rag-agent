## 这份材料解决什么问题

评估器的反馈将用于DeepSeek提出定位策略修改，因此先检查它是否能区分相关与支持、首次取得与重复、必要核实与无增量，以及记录不足时的可判边界。这里的被测对象是评估器，不是mini-agent。仅有正确记录不能识别一律通过的评估器，仅有工具报错也不能检验语义支持判断。

本版以同一DEV-01缴费期限题构造5个候选校准案例：正常新增正例加上4个边界。5只是当前材料数量，不是批准的模型调用数，也不增加v2主集或备用题的执行数量。

统一参照：提交办理请求后一个月内缴费。允许同义表达，但不能换成固定30天。

CAL-01、03、04、05的本次返回保持相同，改变的是前序状态。评估器必须结合前序信息判断，而非只根据当前文本是否正确或是否更长给结论。CAL-02与CAL-01保持题目和前序相同，仅改变返回是否包含必要事实。

“充分”只指本题所需依据，不代表已经检查最终答案、最终引用集合或停止原因。本版没有构造最终答案或停机事件，不能声称四项评测已经全面校准。

## 明确允许与禁止的推断

- CAL-03新增一次调用事件，但此前已取得同源、同内容且可引用的依据。新的调用事件或再次返回正确正文，不代表必要事实或可引用支持能力增加。本例只有不同event_id，没有明示不同evidence_id，不声称已构造证据ID变化反例。
- CAL-04的贡献是对已有事实回源确认及可引用支持提升，必要性来自本组最终引用要求。不能把搜索摘要概括为天然不可信，不能因read更长便判有用，也不能称首次取得该事实。
- CAL-05不能把空的prior_events当作确定的无历史，需看history_prefix_complete=false。可以确认当前条款支持期限，但不能猜测它是否首次取得。
- CAL-02没有期限，所以不能判足证；它是否还提供某种有价值的位置线索，不是本条校准的必判目标，不将局部不充分自动等同整个调用无用。
- 没有任何一条可单独推出“必须修改定位策略”或“候选有效”。事实判断、原因假设及后续对照仍分开。

## 哪些内容给评估器，哪些只用于对账

[结构化案例](cases.json)的每条记录分为：

- `input`：题面、业务题参照、场景前提、前序事件、本次事件。日后获准测试评估器时，用它作为数据输入，并配统一评价规则。
- `proposed_expected_judgment`：这条校准案例应该怎样判的草案，仅给人工审核/独立对账，不传给被测评估器。
- `reviewer_explanation`：编制意图和解释，不传给被测评估器。
- `actual_evaluator_result`：当前均为null，表示没有执行；不可填造通过结果。

业务参照输入不附金标目标行号，减少只按位置对号入座的捷径；实际工具返回仍保留来源位置供核查。正文原始出处在本页与顶层来源说明中可回查。

这里有两层参照：业务题需要哪些事实，本来就是离线评估器的正常输入；评估器对该校准案例应该给什么标签，是测试它时必须隔离的答案。不要把整个cases.json或本README直接塞进被测评估器上下文。

JSON中的建议标签是审阅用表达，不是已经批准的API字段或数值评分规则；语义等价的判断与解释也可接受。评估器须指出实际返回中的依据及缺失项，不能只输出总通过分数。语义判断不取消程序对来源关联、记录完整性和引用真实性的核验。

## 先审阅，再决定如何运行

逐例核查：前提是否足够、原文是否正确、预期是否混淆事实新增与必要核实、unknown是否准确落在不可判断的维度。由用户审阅后，才确定选择哪些案例、用哪个评估模型、重复次数和预算，再决定接口接线；本轮不调用API、不写runner。

本组只覆盖一个简单题目上的基础逻辑，不能证明评估器在多条件、多段组合、矛盾证据或真实长轨迹上可靠。部分案例也可能被简单规则区分，因此通过本组不等于已证明同义改写等更广泛语义判断能力。后续有必要时按已授权范围扩展，不能据5例都通过就宣布全面校准完成；也不能一边据同组结果调整评估器，一边把同组当独立泛化证明。

校准资料仅供评估器设计和审核，不默认交给DeepSeek候选作者，更不能当成mini-agent真实失败轨迹。仅使用D01，没有读取或加入D02/VAL/REG，不改变既有留出隔离。已读过留出的主对话依旧只组织审核。
