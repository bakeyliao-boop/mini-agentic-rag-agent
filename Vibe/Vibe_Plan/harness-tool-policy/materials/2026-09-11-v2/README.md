## 跨段题做实到了什么程度

DEV-04的普通许可规则在D01 L560，最近的开放许可规则在L706，最小连续窗口147行；当前read上限80行，另有限制8000字符。关键词核查未发现短段同时完整给出两类要求。这为跨段取证提供结构依据，但尚未执行Agent，不能宣称已观察到首次读取不足后的自主补读。

两种事项及比较维度已由题面给出，因此它不验证自行发现比较对象或隐含任务分解。可以通过不同工具、并行定位或其他等价原文完成取证，不要求固定读取次数和顺序。其他参考的签章条款也不需全部读取。

VAL-03亦需支持产业到机构、机构到办理方式的对应；不要求在答案中增加另一机构对照。其实际工具路径仍未验证。读取不足、读到后误解、引用不支持和正常或被动结束须分别分析。

## 仍保留的限制

- 改进集的措辞映射覆盖仍偏弱：DEV-02收窄后含明确术语，DEV-04也有正式事项名称；VAL-02保留情景映射。这不是三个难度层级齐全的证明。
- 新DEV-04相关D01开放许可章节含已授权规则，与REG-01有知识重合。REG-01可作停止保护，不是新业务/新规则的泛化证据。
- 两道REG题不覆盖完全无相关资料拒答；本版没有自动增加这类题。
- 北京文档比深圳短且转换方法不同；比较须固定同一文档、索引、路径、模型等输入。不能把两文档分数差直接归因于策略。
- 当前Qwen3.7只完成过配置相关离线检查，八题没有真实运行结果。DeepSeek候选生成、费用和实验执行仍未授权。
- 若原版已充分取证且成本合理，不为证明自进化有效而硬造候选或追加轮数。

候选作者的题目证据输入仅限D01、improvement单道题面以及日后获授权产生的相关改进轨迹；不从全量JSON默认提取更多材料。本README、全量JSON、人审记录、全量协议和交接含留出信息，不得进入候选生成上下文。已读留出的主对话负责组织审核，不充当声称未见留出的策略作者；候选作者人选与程序级隔离仍未落实。
