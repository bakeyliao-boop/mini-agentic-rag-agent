# 首轮真实运行记录最小接线方案

状态：2026-09-14讨论草案；已确认记录原则，具体接线方案尚未授权实施。

## 解决一个问题

让组织者及离线评估器能够从真实记录核对：Agent当时获得了什么、工具调用是否推进取证、内容是否进入后续模型输入。由此为DeepSeek提供可核实的改进侧反馈。不是建设完整日志平台，不要求评估器100%可靠，也不把本方案当作真实策略收益已经成立。

具体链路：模型拿到位置线索 → 提出read → 工具实际返回 → 下一次模型输入 → 后续选择及最终答复。只记录参数和读取行号，无法替代实际返回；事后读取源文件不能补造当时结果。

## 已确认原则

- 工具返回后独立保存，不等下一次LLM调用；下一次LLM调用前保存实际准备交给模型的输入。
- 结果进入模型输入不等于模型有效利用，后者结合后续选择及答复判断。
- 无结果记录不能判工具失败，可能在途、中断或未保存；缺少明确结束依据时标记无法确认。
- 运行后才用金标做离线评价，不将评估侧参照或反馈喂给答题中的Agent。
- 候选先保持答案和引用质量，再看调用贡献与成本。DeepSeek只改位置线索的利用策略，保留Agent工具与自主补证能力。

## 建议的最小记录流程

| 时刻 | 保存的最小内容 | 用途 |
| --- | --- | --- |
| 运行开始 | 题面、统一要求、模型/策略/工具及原文版本、运行标识 | 绑定比较条件，不混淆不同版本 |
| 模型调用前 | 实际组装的system/messages、工具定义与有效模型参数、调用关联 | 查明模型本次被提供的信息；仅记录准备状态不能证明服务端收到 |
| 模型返回或异常 | 实际输出、提出的工具调用、已有usage与结束元数据；可观测异常 | 对应下一步选择；未知用量不能记零 |
| 工具实际执行前 | 名称、参数、现有tool_call_id及提出该调用的模型关联 | 区分模型提出与实际开始执行 |
| 工具返回或异常后 | 完整实际返回或明确异常，read逐条证据ID与出处关联 | 即使没有下一次模型调用，也保留已取得事实 |
| 运行结束或可捕获异常 | 原始结构化输出、实际交付答案与引用、证据检查结果、已观测停因 | 区分内容质量、引用、异常与收口；无明确停因保持未知 |

复用thread/run标识与tool_call_id。仅为区分多次模型请求和记录顺序补本轮序号，不另造业务证据ID体系。同一模型输出可提出多项工具调用，不能假设一对一或由事件先后推定并行关系。

## 当前代码与新增位置

- rag_core/agentic/agent.py的extract_tool_traces只保留调用名称、参数、状态；保留其现有用途，不能把它当完整审计记录。
- rag_core/agentic/runner.py中的invoke/stream、finalize提供运行边界；现有stream的tool_started由AIMessage的工具请求产生，不证明实际工具已开始。不要直接把UI事件名当执行证据。
- rag_core/agentic/tools.py的read已调用EvidenceRegistry并在返回行中附登记ID；复用实际关联，不把整个调用简化成true而默认全部行都支持答案。
- 拟在现有Agent构建/模型和工具执行边界接入可选记录器。具体框架hook及实际能捕获的层级，实施前按已安装版本核查。图状态中的messages不一定等于最终送入模型适配器的输入，不能未经核验就声称记录了完整网络请求。

## 第一轮范围建议

优先做实验用、可关闭的本地逐事件记录，减少部署依赖；这是助手建议，尚非用户批准的选型。保存到独立运行目录，不覆盖历史。Langfuse保持后续可复用选项，不同时建设两套存储。

不改提示词、工具行为、停止机制或预算。记录器不得增加模型上下文或额外模型调用；新增的是本地写入与存储成本，具体字节量和耗时通过离线验证及首轮运行测量。

每个完成事件及时落盘，不只在正常结束时一次性保存。写入失败须显式上报或可检测，相关记录不能冒称完整；进程硬终止下不能保证最后一次写入存在。是否为实验可信性中断本次运行、如何通知组织者，需要在实施范围中明确，不能悄悄改变业务执行控制。

## 如何验证这一项改造

先用离线可控模型和工具检查：正常链路中的关联与实际内容一致；工具返回后无下一次模型调用仍有结果；明确异常与缺失结果区分；多工具调用不串联错误；读登记逐条关联正确；不记录授权头或凭据；关闭记录器保持既有行为。离线测试不访问项目模型API、不建索引。

通过后再拟定一批真实改进题运行。检验评估器是否能根据实际返回给出有依据的判断，而非依据工具类型或预设路线。正常调用保留为正面与回归参照；只有发现真实且值得改的问题，才进入受限候选和对照验证。

若记录改变输入或工具行为、正文缺失、来源关联不清或记录失败却被标完整，先修这一项接线，不把轨迹送去生成策略。即使技术记录完整，评估器仍可能误判，首轮保留人工复核；不靠无限增加模拟题推迟真实链路。
