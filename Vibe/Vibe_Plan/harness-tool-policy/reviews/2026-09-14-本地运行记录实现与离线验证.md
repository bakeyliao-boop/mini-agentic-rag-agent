# 本地运行记录实现与离线验证

日期：2026-09-14。用户确认最小接线方案后实施；本轮没有项目模型API调用、索引构建、策略候选或Git提交推送。

## 已实现

在现有run_agentic_question及stream_agentic_question增加可选recording_dir参数。默认None保持原返回结构和流程；启用时必须指定不存在的新目录，拒绝覆盖旧运行。

新增rag_core/agentic/recording.py，通过项目锁定LangChain 1.3.11的模型/工具回调记录事件，复用callback run_id、tool_call_id并关联提出调用的模型。记录器只写本地文件，不向模型追加内容，不更改提示词、工具、预算或停止中间件。

每个事件写入events.jsonl后flush/fsync；status.json保存运行是否完成、记录故障及未结束观察。保存题面及原文哈希清单、模型输入/输出、工具实际返回（含read行与evidence_id）、明确异常类型、原始结构化输出和实际交付答案。usage缺失保留模型原始null，不把旧汇总中的0当免费。

工具结束回调先保存返回，不依赖下一次模型调用或正常结束。模型请求和工具实际开始分别记录；不能把UI的tool_started事件当工具已执行。并行工具依照标识配对，不依靠顺序猜测。

写入故障警告并使记录完整性为false，不中止或重试Agent；关闭/异常退出时状态为interrupted。只有开始无返回表示结果未知，不自动生成失败事件。硬中断仍可能丢失最后一次写入；status缺失、无法解析或in_progress均不能当完整。目录初始化失败会在Agent运行前拒绝启动。

## 输入层级与可用边界

实际核查已安装langchain_core：on_chat_model_start接收的是_format_for_tracing处理后的消息，模型生成前还有_normalize_messages；因此日志明确标为langchain_pre_normalization_callback，不宣称HTTP请求字节或服务端确实收到了输入。有效参数仅保存回调可见的白名单项；工具定义在回调提供时保存，未提供的参数不能由记录推断。

工具ToolMessage保存实际content和登记ID；这不证明每一行支持答案，也不把回调收到结果等同Agent正确利用。模型输出保留已有结束与用量元数据；运行控制停止原因暂记unknown，不把completed或insufficient猜成预算停止。原始结构化输出与最终答复可对照，但详细证据校验失败子原因尚未细分。

不保存模型序列化配置、授权头或凭据配置；对记录对象中的敏感键及可识别凭据串脱敏。该处理不是任意秘密识别器；被脱敏的内容不能声称逐字原样。首轮仍限获准知识材料，不自动接入生产数据。

history_prefix_complete只表示本次新建Agent、从入口到退出的观察记录未发现写入失败或悬挂调用；不是API投递、底层网络重试或服务端日志完整性的证明。使用前仍应核对事件链及来源。回调级真实API兼容性与存储/耗时成本尚待获准实跑测量。

## 使用

```python
result = run_agentic_question(runtime, question, thread_id,
                              recording_dir=Path("evaluation/results/agent-run-unique-id"))
```

runtime必须由调用方在获准范围内提供；此示例不授权创建索引或调用模型。流式函数支持同名参数。未为Web界面增加记录开关，未新增Langfuse依赖。
